# Muse × Ego：让 AI 通过浏览器插件，在你自己的浏览器里干活

一套实测过的使用方法：让 **Muse**（Meta 的个人 AI）通过官方 Chrome 扩展 **Muse from Meta**，直接控制你本地的 **Ego 浏览器**——用你自己的登录态、你的网络出口，在你的电脑上打开页面、读内容、点按钮、填表单。

不需要云浏览器，不需要远程桌面，不需要任何中继服务。Muse 的"手"就是装在你浏览器里的那个插件。

> 本项目脱胎于一次真实的配置过程（2026-11-13）：从装插件、第一次让它读网页，到摸清 Ego 任务空间（TaskSpace）的真实机制、定下固定用法。踩过的坑都在 [故障排查](docs/故障排查.md) 里。

## 它是怎么工作的

```
你在 Muse 里发一句话（手机/网页/桌面端都行）
        ↓
Muse 通过「设备浏览器」通道下发任务
        ↓
你浏览器里的 Muse from Meta 扩展收到任务
        ↓
扩展操作 Ego 当前聚焦窗口的激活标签：看页面、点击、输入、滚动
        ↓
结果回到 Muse，继续下一步或向你汇报
```

关键事实（实测确认，决定了本项目的用法设计）：

- 扩展是**档案（Profile）级**安装的，它操作的是**当前聚焦窗口的激活标签**，不区分你在哪个"空间"。
- Ego 的**任务空间（TaskSpace）只是页面/工作的分组**，不隔离 Cookie、扩展和登录态——同一档案里的所有空间共享登录态。
- 所以正确的隔离姿势是：**给 Muse 固定一个专属任务空间做页面分区，并让干活时聚焦的窗口停在这个空间里**。分区是给人看的秩序，不是给扩展看的沙箱——想通这一点，后面的约定才成立。

## 快速开始

1. **装 Ego 浏览器**（Chromium 内核，支持 Chrome 扩展；本方法在普通 Chrome 上同样成立，只是没有任务空间可用）。
2. **装扩展**：在浏览器里安装 **Muse from Meta**（认准发行方 Meta，扩展商店里有仿冒品），用你的 Meta 账号登录。
3. **连 Muse**：在 Muse 的对话里发起一个需要浏览器的任务，选择使用你这台设备上的浏览器；扩展侧按提示确认连接。
4. **建分区**：在 Ego 里新建一个任务空间，命名为 `Muse`（命名约定见下文），把 Muse 要用的页面都开在这个空间里。
5. **立规矩**：把 [《给 Muse 的浏览器使用约定》](templates/给-Muse-的浏览器使用约定.md) 发给你的 Muse，让它以后固定按这套规则用你的浏览器。

## 固定用法（本项目的核心约定）

| 约定 | 说明 |
|---|---|
| 固定空间名 `Muse` | 所有浏览器任务都在这个空间里做；空间随标签全关或浏览器重启会消失，下次按同名重新打开即可（Ego 的空间是"按名使用、没有就新建"的语义，不需要预先维护） |
| 干活时保持聚焦 | 让 Muse 干活时，把停在 Muse 空间的窗口保持在前台——扩展操作的是聚焦窗口的激活标签 |
| 不碰你的空间 | 你自己的标签留在你自己的空间里，约定 Muse 只动 Muse 空间内的页面 |
| 卡点交还 | 遇到登录、验证码、支付这类只能你本人完成的步骤，Muse 停下来等你处理完再继续，不要让它硬闯 |
| 云浏览器仅限指定任务 | Muse 自带的云浏览器只用于你明确指定采用它的任务（包括你事先安排好、已在云浏览器上跑的定时任务），其余任务一律走本地浏览器 |
| 不用无头浏览器 | 这套方法只用真实浏览器 + 官方插件；不要再另搭无头浏览器/自建自动化通道，那类方案已弃用 |

## 安全提醒

- 只装官方 **Muse from Meta**，认准发行方；同类仿冒扩展会窃取页面数据。
- 这套方法等于让 AI 用**你的登录态**浏览网页：只在你信任的设备和档案上启用；敏感页面（银行、支付）不要放进 Muse 的空间。
- 空间分区**不是**安全隔离：同一档案内登录态共享。真要硬隔离，请使用独立的浏览器档案（Profile），代价是登录态要单独维护一份。
